# external-review-reply

외부 전문가의 초안을 검토해 돌려보내는 글의 문체와 절차다. 2026-10-13 특허 초안 댓글 26개를 다듬으며 확정했다. 내부 Slack 본문은 이 스킬 대상이 아니다(합쇼체 보고문 그대로).

## 독자 먼저 정한다

- 파일(docx 댓글)의 독자는 초안을 쓴 전문가다. 의뢰인(대표)이 준 검토 항목 틀을 그 파일에 쓰지 않는다. 의뢰인용 요약은 Slack이나 메일 본문에 따로 쓴다.
- 검토자는 발명자나 출원인이나 계약 당사자가 아니다. 댓글에 방침 선언, 일정 결정, 명의나 권리 귀속 언급, 조문 번호 단정, 의뢰인 대상 문장을 넣지 않는다. 결정이 필요한 항목은 "출원인(의뢰인)이 확정해 회신드리겠습니다"로 쓴다.

## 어투

- 평서문은 합쇼체. "~입니다", "~습니다".
- 질문만 해요체. "인가요?", "어떠세요?", "있나요?", "가능한가요?".
- 판정어 금지. "맞습니다", "적절합니다", "맞아 보입니다" 대신 "확인했습니다", "동의합니다".
- 명령형 금지. "바꿔 주세요", "고쳐 주세요", "넣으면 됩니다", "빼 주시면 됩니다" 대신 "변경 부탁드립니다", "검토 부탁드립니다", "확인 부탁드립니다".
- "고치다"는 틀렸다는 함의가 있어 "변경"으로. 질문 마무리는 "알려 주시면 감사하겠습니다".

## 문장

- 조각 문장 금지. "보완 가능.", "탐색은 A 또는 B.", "미구현이므로 '일 실시예에서' 수준으로." 같은 명사 종결은 완전한 문장으로 푼다.
- 요청 하나당 한 줄. 요청이 둘 이상이면 줄바꿈으로 나눈다.
- 나열을 묶을 때는 쉼표 대신 "및".
- 댓글 앞 분류 라벨("답변.", "권고.")을 붙이지 않는다.
- em dash, en dash, 가운뎃점, 화살표를 쓰지 않는다.

## 참조

- 내가 변환한 txt의 줄 번호([155], [0113])를 문단 번호처럼 쓰지 않는다. 상대 문서에 그 번호가 실제로 있는지 grep으로 먼저 확인한다. 공개공보에는 【0037】 문단 번호가 있지만 변리사 초안 docx에는 없다.
- 번호가 없으면 문장 인용("'...을 산출하여' 문장"), 빨간 글씨 제목, 청구항 번호, 섹션명으로 가리킨다.
- 총평에서 개별 댓글을 가리킬 때는 "(청구항 2 댓글)", "(명칭 댓글)"처럼 앵커 이름으로.

## 총평 구조

검토의뢰서의 "[발명자 초안검토 의견]" 같은 회신 칸에 댓글로 단다. 본문은 수정하지 않는다.

```
검토 의견입니다.
빨간 글씨 N곳은 각 위치에 댓글로 답했습니다. (한 줄 현황)

수정 검토 요청
1. 요청. 근거 한 문장(가리킬 댓글).
2. ...

확인 질문
가. 질문. 알려 주시면 감사하겠습니다.
나. ...
```

## docx 댓글 생성

`scripts/add_comments.py`가 python-docx 1.2의 `add_comment`로 본문 무수정 댓글을 단다. 앵커 문자열로 문단을 찾고 표 셀도 훑는다.

```
uv run --quiet --with 'python-docx>=1.2' python -I scripts/add_comments.py spec.json
```

spec.json 형식과 검증 항목은 스크립트 상단 docstring 참고. 입력 docx는 untrusted 디렉터리에 두고 `-I`로 실행한다. 받은 docx는 먼저 숨은 텍스트(vanish, 흰 글씨, 극소 폰트, 텍스트 상자, 메타데이터)를 훑는다.

## 발송 전 점검

1. 본문이 원본과 동일한지(스크립트가 검증).
2. 금지 문자 0건: `grep -P '[\x{2014}\x{2013}\x{00B7}\x{2192}]'`.
3. 줄 번호 참조 0건: `grep -E '\[0?[0-9]{3}\]'`.
4. 판정어와 라벨 0건: `grep -E '답변\.|권고\.|맞습니다|적절하|맞아 보입니다'`.
5. 모든 줄이 완전한 문장으로 끝나는지.
6. 외부로 가는 검토물은 건당 독립 에이전트로 원문 대조(자체 재검토는 전제 오류를 못 본다).

전후 예시는 `examples.md`.
